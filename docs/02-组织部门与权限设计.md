# 02 - 组织部门与权限设计

> **文档状态**：Draft 0.4  
> **上级文档**：[00-项目管理服务设计文档索引](./00-项目管理服务设计文档.md)

---

## 1. 权限设计目标

权限不要做成复杂的“部门 + 角色 + 任务参与人 + 上级链路 + 动态拒绝规则”混合系统。第一版只保留三类可解释来源：

1. 超级管理员。
2. 直接项目成员。
3. 项目部门授权。

父子部门只负责部门信息可见性和部门授权展开，不让任务负责人、评论人、创建人反向扩大项目访问权限。

---

## 2. 角色定义

| 角色 | 数据表达 | 说明 |
|---|---|---|
| 超级管理员 | `users.system_role = super_admin` | 可查看和管理所有部门、项目、任务、成员、日志、导出 |
| 普通用户 | `users.system_role = user` | 具体项目权限由项目成员和部门授权决定 |
| 部门负责人 | `user_departments.role = manager` | 可维护本部门信息；可查看下级部门信息；不自动成为项目负责人 |
| 部门成员 | `user_departments.role = member` | 可查看本部门和下级部门基础信息 |
| 项目负责人 | `project_members.role = manager` | 一个项目可有多个负责人 |
| 项目成员 | `project_members.role = member` 或部门授权 `member` | 可创建、编辑、删除任务和改状态 |
| 观察者 | `project_members.role = viewer` 或部门授权 `viewer` | 只读项目和任务 |

## 3. 部门可见性

部门是树结构：

```text
公司
├── 产品部
│   ├── 产品一组
│   └── 产品二组
├── 研发部
│   ├── 前端组
│   └── 后端组
└── 交付部
```

部门信息查看规则：

1. 超级管理员可以查看所有部门信息。
2. 用户可以查看自己所属部门的信息。
3. 父部门用户可以查看所有下级部门信息。
4. 下级部门用户不能因为自己属于子部门就自动查看父部门下的兄弟部门详情，除非同时属于父部门或被授予相关项目权限。
5. 部门信息可见不等于项目任务可写；任务读写仍看项目有效角色。

实现建议使用 `department_closure`：

```text
department_closure(ancestor_id, descendant_id, depth)
```

判断“用户是否可查看部门 D”：

```text
super_admin
OR user_departments.department_id = D
OR user_departments.department_id 是 D 的祖先部门
```

## 4. 项目有效角色

项目有效角色按最高权限计算：

```text
effective_project_role = max(
  super_admin,
  direct project_members role,
  project_department_grants role after department hierarchy expansion
)
```

角色强度：

```text
super_admin > manager > member > viewer > none
```

规则：

1. 超级管理员对所有项目有效角色为 `super_admin`。
2. 项目负责人必须来自 `project_members.role = manager`，部门授权不能产生负责人。
3. 项目成员可来自直接项目成员，也可来自部门授权。
4. 项目部门授权只允许 `member` 或 `viewer`，不允许 `manager`。
5. 用户属于多个部门时，取所有部门授权中的最高角色。
6. 创建项目时，系统自动为主项目部门写入一条 `member` 授权；额外部门必须显式配置。
7. 如果项目授权给父部门并设置 `include_children = true`，下级部门用户继承该项目授权。
8. 如果项目授权给子部门，父部门用户不会自动获得该项目任务权限；如果需要父部门参与项目，显式授权父部门或直接加入项目成员。
9. 不提供显式 deny 规则，避免“同一用户既被部门授权又被项目拒绝”的复杂冲突。

## 6. 核心表结构

### `users`

- `id uuid primary key`
- `account varchar(80) not null unique`
- `display_name varchar(120) not null`
- `email citext null unique`
- `avatar_url text null`
- `password_hash text not null`
- `system_role varchar(32) not null default 'user'`：`super_admin | user`
- `is_active boolean not null default true`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

用户禁用和删除都不物理删除：禁用使用 `is_active=false`；删除写 `deleted_at/deleted_by`。

### `departments`

- `id uuid primary key`
- `parent_id uuid null references departments(id)`
- `code varchar(40) not null unique`
- `name varchar(120) not null`
- `position integer not null default 0`
- `is_active boolean not null default true`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

部门删除也是逻辑删除。存在未删除子部门或未归档项目时，第一版建议拒绝删除该部门。

### `department_closure`

- `ancestor_id uuid not null references departments(id)`
- `descendant_id uuid not null references departments(id)`
- `depth integer not null`
- 主键：`(ancestor_id, descendant_id)`

闭包表用于快速判断父子部门和 `include_children` 授权。

### `user_departments`

- `user_id uuid not null references users(id)`
- `department_id uuid not null references departments(id)`
- `role varchar(32) not null default 'member'`：`manager | member`
- `is_primary boolean not null default false`
- `revoked_at timestamptz null`
- `created_at timestamptz not null`
- 主键：`(user_id, department_id)`

用户可属于多个部门；移出部门写 `revoked_at`，不物理删除。

### `project_members`

- `project_id uuid not null references projects(id)`
- `user_id uuid not null references users(id)`
- `role varchar(32) not null`：`manager | member | viewer`
- `source varchar(32) not null default 'direct'`
- `revoked_at timestamptz null`
- `created_by uuid not null references users(id)`
- `created_at timestamptz not null`
- 主键：`(project_id, user_id)`

创建项目时必须同时创建至少一条 `manager` 成员记录。移除或降级负责人时，应用层必须拒绝“最后一个负责人被移除”的操作。

### `project_department_grants`

- `project_id uuid not null references projects(id)`
- `department_id uuid not null references departments(id)`
- `role varchar(32) not null`：`member | viewer`
- `include_children boolean not null default false`
- `revoked_at timestamptz null`
- `created_by uuid not null references users(id)`
- `created_at timestamptz not null`
- 主键：`(project_id, department_id)`

移除部门授权写 `revoked_at`，不物理删除。

## 7. 权限测试用例

阶段 0 必须至少覆盖：

1. 超级管理员能查看所有部门和项目。
2. 父部门用户能查看所有下级部门信息。
3. 子部门用户不能自动查看兄弟部门信息。
4. 部门负责人能创建本部门项目，并自动成为项目负责人。
5. 项目有多个负责人时，任意负责人可管理成员。
6. 尝试移除最后一个项目负责人失败。
7. 直接跨部门成员可访问被加入的项目，但不获得其原部门之外的其他项目权限。
8. 项目成员可删除任务但不能恢复任务。
9. 观察者不能创建、修改、删除任务。
10. 未授权用户手工构造 API 请求也不能读取任务详情。
