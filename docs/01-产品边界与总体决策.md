# 01 - 产品边界与总体决策

> **文档状态**：Draft 0.4  
> **上级文档**：[00-项目管理服务设计文档索引](./00-项目管理服务设计文档.md)

---

## 1. 产品定位

Projecty 是单公司内部使用的项目管理服务，只做项目管理，不扩展成研发平台、ERP、客服工单或外部协作门户。

目标形态是一个类似 JIRA 的项目工作台，但第一版只实现项目管理主链路：

```text
部门 -> 项目 -> 项目成员/项目负责人 -> 任务/子任务 -> 状态 -> 操作日志
```

---

## 2. 已确认决策

| 主题 | 决策 |
|---|---|
| 部署边界 | 单公司内部系统，不做多租户 SaaS |
| 账号体系 | 本地账号 + 密码登录 |
| 鉴权 | JWT |
| 超级管理员 | `super_admin` 可查看和管理所有数据 |
| 部门结构 | 用户可属于多个部门，部门支持父子层级 |
| 父部门可见性 | 父部门用户可以查看所有下级部门信息 |
| 项目负责人 | 一个项目允许多个负责人，不使用单一 `owner_id` |
| 项目成员 | 可创建、编辑、删除任务和修改任务状态 |
| 任务层级 | 只支持任务和子任务两层，子任务不能再有子任务 |
| 删除策略 | 所有删除均为逻辑删除 |
| 操作日志 | 任务新增、删除、状态修改必须写日志 |
| 日志导出 | 需要支持导出，不脱敏 |
| 任务规模 | 按 1,000,000 条任务设计 |
| 前端形态 | SvelteKit 多页面复杂 Web 应用，不做单页 Demo |
| 样式约束 | 不使用 Tailwind CSS，不使用 Inter/Intel One/Roboto 主字体 |

---

## 3. 第一版包含

| 领域 | 第一版能力 | 说明 |
|---|---|---|
| 用户与部门 | 本地账号、密码登录、部门层级、用户多部门归属 | 超级管理员可查看全部；父部门可查看下级部门信息 |
| 项目 | 项目创建、编辑、归档、恢复、项目概览、多负责人 | 项目必须归属一个主项目部门 |
| 项目成员 | 项目负责人、项目成员、观察者、跨部门成员 | 直接项目成员可跨部门 |
| 任务 | 创建、编辑、删除、负责人、优先级、标签、截止日期 | 删除采用逻辑删除 |
| 子任务 | 父任务下创建子任务、子任务状态跟踪 | 子任务不能再有子任务 |
| 状态 | 可配置状态列、拖拽流转、状态变更校验 | 默认：待办、进行中、评审、已完成、已取消 |
| 视图 | 看板、列表、时间线、日历 | 同一任务数据的不同投影 |
| 里程碑 | 创建、截止日期、达成状态、关联任务 | 项目交付节点，不等同于状态列 |
| 依赖 | 任务阻塞/被阻塞关系 | 禁止自依赖和循环依赖 |
| 操作日志 | 查询、项目日志、任务日志、导出 | 导出不脱敏，但必须鉴权 |
| 体验 | 搜索入口、项目内筛选、快捷创建、弹窗/抽屉详情 | 任务详情可深链 |

## 4. 明确不做

第一阶段不做：

- 多租户 SaaS、外部客户门户、跨公司协作。
- 代码托管、Pull Request、CI/CD、发布流水线。
- 工单客服、SLA、知识库。
- 工时填报、计费、预算、发票、采购。
- 原生桌面端、原生移动端。
- 复杂即时聊天、视频会议。
- 邮件驱动任务创建、邮件别名、外部客户邀请。
- 第一版第三方集成，例如 GitHub、GitLab、Slack、飞书。
- 第一版 OIDC/LDAP；后续如公司统一身份系统要求再扩展。
- AI 自动生成项目计划作为核心流程。

---

## 5. 规模约束

用户规模：10–50 人。  
任务规模：约 1,000,000 条任务。

这个规模对 PostgreSQL 和 Rust 服务端不是异常规模，但 UI 和 API 不能当作小数据处理：

- 看板按项目和状态列分批加载。
- 任务列表使用 cursor/keyset pagination。
- 默认过滤逻辑删除数据。
- 搜索先做项目内标题/编号搜索，后续再评估 PostgreSQL full-text search 或专用搜索服务。
- 项目概览统计避免每次实时大范围 `count(*)`。
- 阶段 0 必须准备百万任务种子数据做查询计划和首屏耗时验证。
