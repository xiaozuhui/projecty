## 1. 领域关系

```text
Project
 ├── ProjectStatus
 ├── Milestone
 └── Task
      ├── Subtask(Task.parent_task_id)
      ├── TaskDependency
      ├── TaskComment
      └── OperationLog
```

任务层级只允许两层：

```text
任务
└── 子任务
```

子任务不能再创建子任务。数据库字段仍使用 `parent_task_id`，但 application service 必须强制校验父任务本身没有 `parent_task_id`。

## 2. 逻辑删除总原则

所有删除都采用逻辑删除，不物理删除业务数据：

| 对象 | 删除字段建议 | 说明 |
|---|---|---|
| 用户 | `deleted_at`, `deleted_by`，同时 `is_active=false` | 保留历史操作人、负责人、评论作者 |
| 部门 | `deleted_at`, `deleted_by` | 存在子部门或项目时拒绝删除 |
| 项目 | `archived_at`, `archived_by`；如需删除再加 `deleted_at` | 第一版优先归档，不物理删除 |
| 项目成员 | `revoked_at` | 退出项目保留成员历史 |
| 部门授权 | `revoked_at` | 保留授权变更历史 |
| 任务/子任务 | `deleted_at`, `deleted_by`, `delete_reason` | 删除后普通列表不可见，日志仍可查 |
| 里程碑 | `deleted_at`, `deleted_by` | 保留关联任务历史 |
| 依赖关系 | `deleted_at`, `deleted_by` | 解除依赖也可追溯 |
| 评论 | `deleted_at`, `deleted_by` | 删除评论保留审计痕迹 |
| 操作日志 | 不提供业务删除 | 只追加，清理走独立保留策略 |

所有删除动作必须写操作日志。任务/子任务删除日志是第一版必做能力。

## 3. 项目表

### `projects`

- `id uuid primary key`
- `owner_department_id uuid not null references departments(id)`
- `key varchar(16) not null unique`
- `name varchar(160) not null`
- `description text null`
- `status varchar(32) not null`：`planned | active | on_hold | completed | archived`
- `start_date date null`
- `due_date date null`
- `task_number_seed bigint not null default 0`
- `version bigint not null default 1`
- `created_by uuid not null references users(id)`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- `archived_at timestamptz null`
- `archived_by uuid null references users(id)`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- 检查约束：`due_date is null or start_date is null or due_date >= start_date`

项目负责人不放在 `projects.owner_id`，而由 `project_members.role = manager` 表达。

## 4. 状态表

### `project_statuses`

- `id uuid primary key`
- `project_id uuid not null references projects(id)`
- `name varchar(80) not null`
- `category varchar(32) not null`：`todo | active | review | done | canceled`
- `color varchar(32) not null`
- `position integer not null`
- `is_terminal boolean not null default false`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_at timestamptz not null`
- 唯一约束：`(project_id, name)`、`(project_id, position)`

状态名称可配置，但 `category` 是系统稳定语义。拖拽只是状态变更入口之一，必须复用同一个 `transition_task` 用例。

## 5. 任务与子任务表

### `tasks`

- `id uuid primary key`
- `project_id uuid not null references projects(id)`
- `parent_task_id uuid null`
- `number bigint not null`
- `title varchar(240) not null`
- `description text null`
- `status_id uuid not null references project_statuses(id)`
- `priority varchar(16) not null`：`urgent | high | medium | low | none`
- `assignee_id uuid null references users(id)`
- `reporter_id uuid not null references users(id)`
- `milestone_id uuid null references milestones(id)`
- `due_date date null`
- `position numeric(24,10) not null`
- `version bigint not null default 1`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- `completed_at timestamptz null`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `delete_reason text null`
- 唯一约束：`(project_id, number)`、`(project_id, id)`
- 复合外键：`(project_id, parent_task_id) -> tasks(project_id, id)`
- 检查约束：`parent_task_id is null or parent_task_id <> id`

业务编号：`{PROJECT_KEY}-{number}`，例如 `PROJ-42`。

### 子任务规则

1. 父任务：`parent_task_id is null`。
2. 子任务：`parent_task_id` 指向同项目的父任务。
3. 子任务不能再有子任务：创建子任务时必须校验父任务的 `parent_task_id is null`。
4. 禁止跨项目父子关系：复合外键保证同项目。
5. 父任务存在未删除子任务时，第一版拒绝删除父任务。
6. 删除子任务只逻辑删除当前子任务，不影响父任务。
7. 父任务和子任务状态不自动联动；父任务详情页只展示子任务完成度。
8. 子任务和父任务共用同一套权限：用户必须对项目具备 `member` 及以上角色才能创建、编辑、删除或改状态。

## 6. 任务状态机

默认状态：

```text
待办(todo) -> 进行中(active) -> 评审(review) -> 已完成(done)
     │             │               │
     └─────────────┴───────────────┴──> 已取消(canceled)
```

规则：

1. 每个状态列必须映射到稳定 `category`。
2. `done` 要求记录 `completed_at`。
3. 从 `done` 回退时，要写操作日志说明完成时间变化。
4. 状态变更必须检查项目是否归档、用户权限、目标状态是否合法、依赖是否阻塞完成。
5. 看板拖拽、详情页状态选择、列表批量状态修改必须复用同一个用例。
6. 任务创建、任务删除、任务状态修改必须和操作日志同事务提交。

## 7. 里程碑、依赖、评论

### `milestones`

- `id uuid primary key`
- `project_id uuid not null references projects(id)`
- `name varchar(160) not null`
- `description text null`
- `due_date date null`
- `is_reached boolean not null default false`
- `reached_at timestamptz null`
- `position integer not null`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

### `task_dependencies`

- `project_id uuid not null references projects(id)`
- `blocking_task_id uuid not null`
- `blocked_task_id uuid not null`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_by uuid not null references users(id)`
- `created_at timestamptz not null`
- 主键：`(project_id, blocking_task_id, blocked_task_id)`
- 复合外键保证两个任务属于同一项目
- 检查约束：两者不能相等

新增依赖时必须在事务中检查是否形成环。解除依赖写逻辑删除字段。

### `task_comments`

- `id uuid primary key`
- `task_id uuid not null references tasks(id)`
- `author_id uuid not null references users(id)`
- `body text not null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`

## 8. 标签

任务标签用于轻量分类，不参与权限计算。

### `task_labels`

- `id uuid primary key`
- `project_id uuid not null references projects(id)`
- `name varchar(60) not null`
- `color varchar(32) not null`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_at timestamptz not null`
- 唯一约束：`(project_id, name)`

### `task_label_links`

- `task_id uuid not null references tasks(id)`
- `label_id uuid not null references task_labels(id)`
- `deleted_at timestamptz null`
- `deleted_by uuid null references users(id)`
- `created_at timestamptz not null`
- 主键：`(task_id, label_id)`

移除标签或解除任务标签关系都写逻辑删除字段。

## 9. 乐观并发

所有可编辑资源带 `version`。更新请求携带客户端看到的版本：

```http
PATCH /api/v1/tasks/PROJ-42
If-Match: "7"
```

版本不一致返回 `409 Conflict`，避免两个浏览器同时编辑时后保存者静默覆盖前者。

## 10. 拖拽排序事务

看板拖拽需要同时改变状态和位置，必须是一个事务：

1. 校验 JWT、项目权限和任务版本。
2. 校验目标状态属于当前项目。
3. 计算新的 `position`。
4. 更新任务 `status_id`、`position`、`version`。
5. 写入 `operation_logs`。
6. 提交事务。

## 11. 当前代码实现基线（2026-08-30）

当前后端已经落地任务领域的第一版闭环：

- `backend/src/modules/tasks/` 提供项目任务、任务详情、子任务、更新、状态流转、逻辑删除和恢复接口。
- 任务与子任务共用 `tasks` 表；创建子任务时校验父任务不能本身是子任务，因此最大层级固定为两层。
- 项目使用 `task_number_seed` 原子递增分配任务编号，任务 Key 为 `{PROJECT_KEY}-{number}`。
- 任务创建、普通字段更新、状态流转、逻辑删除和恢复均在业务变更事务内写入 `operation_logs`。
- 归档项目禁止新增或修改任务；读取和日志查询仍按权限执行。
- 列表首版使用固定排序与受限分页（单页最多 100 条），后续看板和百万级深分页场景仍需切换到 cursor/keyset pagination。

当前实现尚未覆盖版本号/`If-Match` 乐观锁、位置排序、批量状态修改和任务依赖；这些功能不能被当前接口默认推断为已实现。
