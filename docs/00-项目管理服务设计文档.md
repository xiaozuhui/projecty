## 2. 当前已确认的核心决策

1. **单公司内部系统**：不做多租户 SaaS，不把 `organization_id` 作为第一版业务表必需字段。
2. **本地账号登录**：统一使用账号和密码登录；鉴权使用 JWT；密码只保存 hash。
3. **超级管理员**：`super_admin` 可以查看和管理所有部门、项目、任务、成员、操作日志和导出。
4. **多项目负责人**：一个项目可以有多个负责人，由多条 `project_members.role = manager` 表达；不使用单一 `owner_id` 作为业务真源。
5. **部门层级**：用户可以属于多个项目部门；父部门用户可以查看所有下级部门信息；项目权限仍主要通过直接项目成员和项目部门授权计算。
6. **项目成员操作任务**：项目成员可以创建任务、编辑任务、修改任务状态、删除任务；关键任务操作必须写操作日志。
7. **任务与子任务**：只支持“任务 -> 子任务”两层；子任务不能再有子任务。
8. **所有删除都是逻辑删除**：API 上的删除行为必须写 `deleted_at/deleted_by/delete_reason`、`archived_at` 或 `revoked_at` 等状态字段，不做业务数据物理删除。
9. **操作日志导出**：第一版需要支持操作日志导出；公司内部系统不做脱敏，但导出动作本身必须鉴权并写日志。
10. **规模假设**：用户约 10–50 人，任务总量按 1,000,000 条设计；PostgreSQL + Rust 可以承载，但 API/UI 必须分页、索引、分批加载。
11. **复杂 Web 前端**：使用 SvelteKit 多页面/嵌套路由，不做单页 Demo；网页端需要桌面、平板、窄屏动态伸缩。
12. **视觉约束**：不使用 Tailwind CSS；不使用 Inter/Intel One/Roboto 作为主字体；参考用户 HTML 中的浅色工作台风格。

## 3. 推荐阅读顺序

1. 先读 [01-产品边界与总体决策](./01-产品边界与总体决策.md)，确认首版范围。

## 4. 第一阶段主链路

```text
部门/父子部门
  -> 项目
    -> 多项目负责人 / 项目成员 / 部门授权
      -> 任务 / 子任务
        -> 状态流转 / 逻辑删除
          -> 操作日志 / 导出
```

首版不要把未来集成和“看起来像 JIRA 的所有功能”都塞进来，优先保证权限、任务、子任务、状态、逻辑删除、日志和百万级查询这些基础能力正确。
